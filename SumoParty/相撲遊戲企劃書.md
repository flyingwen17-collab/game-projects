## 1. 一頁概要

| 項目 | 內容 |
|------|------|
| 一句話 | 全家人圍著 iPad 或電腦,用一根手指互推相撲,把對方擠出土俵就贏 |
| 核心循環 | 選力士 → 立合開戰(15~45 秒)→ 勝負演出 → 「再來一場!」 |
| 維度 | **3D**(核心樂趣靠土俵空間感與推擠物理,符合流程 MD 的 3D 判準) |
| 視角 | 第三人稱(單人模式在自己力士後上方;多人模式斜俯環繞,見 §6) |
| 玩家 | 1 人(vs NPC)~ 4 人同機同樂 |
| 平台 | **WebGL 網頁版**:iPad Safari + Windows 瀏覽器一份程式通吃;Windows 另出離線 exe |
| 目標客群 | 5 歲小孩到 80 歲長輩,零遊戲經驗也能玩 |
| 美術風格 | **日本傳統相撲 × 可愛寫實風**:Q 版比例(2.5 頭身圓潤體型)+ 寫實相撲細節(廻し、鹽、行司、軍配、土俵俵繩) |
| 目標 | 家庭聚會實用 + 作品集;完成後上 itch.io |

### 三根柱子(所有功能都要掛得上,掛不上就不做)

1. **三秒懂**:被推出圈外就輸——不用教學,阿嬤和幼稚園小孩看一眼就會。
2. **一指玩**:全部操作 = 點擊 + 滑動,單指完成。沒有搖桿、沒有組合鍵。
3. **圍爐感**:iPad 平放桌上 2~4 人圍著戳,像玩桌遊;輸贏都有可愛演出,輸了力士鞠躬(順便教相撲禮儀)。

## 2. 玩法規則

### 2.1 勝負規則(刻意簡化)

- **唯一敗北條件:整個人出土俵圈外**(判定用角色重心過俵繩)。
- 真實相撲的「手/膝觸地也輸」**不採用**——對幼兒與長輩太嚴苛,也讓物理判定變複雜。被打倒只會原地爬起(有 1 秒硬直),增加喜感不增加挫折。
- 一番(回合)15~45 秒;**30 秒未分勝負 → 土俵開始緩慢縮圈**,強制決著,不會僵持。
- 正式對戰採**三戰兩勝**;派對模式可設一戰定勝負。

### 2.2 操作(觸控與滑鼠同一套邏輯)

| 操作 | 效果 | 備註 |
|------|------|------|
| 點一下 | 向前推一掌(連點=連推,但消耗「氣力」條) | 核心動作 |
| 左/右滑 | 橫移閃避一步 | 對手撲空會前傾硬直 0.5 秒 |
| 往下滑(往自己) | 扎馬步:3 秒內被推距離減 70%,但不能移動 | 防禦 |
| 點技能鈕 | 發動角色專屬技(氣槽滿才亮起) | 大按鈕,亮起會發光提示 |

- **氣力條**:狂連點會喘(推力遞減),逼玩家抓節奏而不是拚手速——這是長輩和小孩公平對戰的關鍵設計。
- Windows 鍵盤替代:P1 = WASD 移動 + J 推 + K 技能;P2 = 方向鍵 + 數字鍵 1 推 + 2 技能。滑鼠玩家:點擊=推、拖曳=移動。

### 2.3 遊戲模式

| 模式 | 人數 | 內容 | 平台支援 |
|------|------|------|----------|
| 橫綱之路(單人) | 1 + NPC | 8 連戰番付爬升:序之口→…→橫綱,每勝一場觀眾變多、幕變豪華 | iPad / Win |
| 兩人對戰 | 2 | 正規 1v1 三戰兩勝,iPad 平放各佔半邊觸控區 | iPad / Win(鍵盤分區) |
| 土俵大亂鬥 | 3~4 | 全員同時上土俵,最後留在圈內者勝(縮圈加速) | **iPad 專屬**(平放,四角觸控區;Win 鍵盤塞不下 4 人,不支援) |
| 巴戰錦標賽 | 3~4 輪流 | 1v1 淘汰賽自動排程,沒上場的人當觀眾按加油鈕(丟座墊特效) | iPad / Win |

- NPC 難度三段:**見習**(會自己失去平衡,保證小孩長輩贏得了)/ **關取**(正常)/ **橫綱**(會讀你的節奏)。

### 2.4 一場的儀式感(可比照真實相撲的部分)

開場固定演出(可跳過):力士入場 → 撒鹽 → 四股踏 → 行司舉軍配喊「はっけよい!」→ 開戰。勝負後:勝方可愛慶祝、敗方起身鞠躬、行司指向勝方。**全程無文字也看得懂。**

## 3. 五位力士(首發陣容)

> 造型原則:同一套 3D 素體 + 身材參數(高矮胖瘦縮放)+ 膚色/臉/廻し貼圖替換 → **一個模型生五個角色**,這是 3D 工作量可控的核心手段。

| 力士 | 原型/身材 | 膚色 | 屬性(推力/移動/穩定,滿分 5) | 專屬技(氣槽滿發動) |
|------|-----------|------|------------------------------|----------------------|
| **大山 剛**(巨漢型) | 日本傳統橫綱體型,最壯 | 淺 | 5 / 1 / 4 | 「怒濤張手」:大力一掌,擊中者被推飛一大段 |
| **疾風丸**(少年型) | 瘦小敏捷,最小隻 | 小麥 | 2 / 5 / 2 | 「燕返」:瞬間繞到對手側面 |
| **武藏島**(夷州巨漢) | 致敬夏威夷出身力士(小錦/曙),最重 | 深 | 4 / 2 / 5 | 「岩盤仁王立」:4 秒內完全推不動 |
| **櫻**(女力士) | 勻稱平衡型 | 白皙 | 3 / 3 / 3 | 「猫騙」:拍掌讓正面對手硬直 1.2 秒 |
| **銀嶽**(老將) | 銀髮精瘦,技巧派 | 偏深的曬色 | 2 / 3 / 4 | 「後之先・上手投」:被推瞬間發動,把對手過肩甩半圈(反擊技) |

- 五角刻意覆蓋:老中青、男女、三種膚色、四種身材——全家每個人都找得到「像自己的」。
- 屬性總分接近(12~13),無強弱角,差異是玩法風格不是數值碾壓。
- 角色個性只靠外觀與勝利動作表達,**無語音無文字**。

## 6. 攝影機(第三人稱的兩套方案)

| 模式 | 攝影機 | 理由 |
|------|--------|------|
| 單人(橫綱之路) | **背後第三人稱**:自己力士後上方 15° 俯角,對手在正前 | 使用者指定的第三人稱體驗,單人時成立 |
| 2~4 人同螢幕 | **環繞第三人稱**:斜俯 35° 拍全土俵,隨戰況緩慢環繞;誰被逼到俵際就拉近誰 | 同一螢幕多人不可能各自背後視角,以「電視轉播感」取代 |
| 勝負瞬間 | 慢動作 + 特寫(出圈的 0.5 秒) | 全場最爽的一刻,重點演出 |

## 7. 技術規格

- **引擎**:Unity 2022.3.36f1(G:\Unity,環境細節見專案 CLAUDE.md)+ URP
- **Unity 專案名**:`SumoParty\`(英文路徑,依流程 MD §6.1)
- **目標平台**:WebGL(主)→ iPad Safari / Win 瀏覽器;Windows exe(副,同一份專案切 build target)
- **WebGL 鐵則**(iPad Safari 是效能下限):
  - 記憶體 heap ≤ 512MB;貼圖最大 1024;總面數上限 15 萬三角面
  - 音訊需首次觸控解鎖(進場「點擊開始」畫面順便解)
  - 橫向優先,直立時顯示「請轉橫」提示
  - 後處理:Bloom 低強度 + ACES;iPad 偵測到低效能自動關 Bloom
  - 目標 60 FPS(Win)/ 30 FPS 穩定(2020 年後 iPad)
- **輸入**:Unity Input System,觸控與滑鼠鍵盤同一套 action;多人觸控用螢幕分區(EnhancedTouch 多點)
- **物理**:Rigidbody + 自訂推擠力模型(推力對抗「穩定」屬性與重心),FixedUpdate 50Hz;手感參數全部進 ScriptableObject,灰盒期調
- **NPC AI**:狀態機(逼近/推/閃/防/放技),難度=反應延遲與失誤率參數,不寫複雜行為樹
- **存檔**:PlayerPrefs(解鎖進度、速度偏好)——WebGL 用 IndexedDB 自動處理

## 9. 風險表(本專案特有)
